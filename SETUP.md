# How this page is built

Everything on the profile is an SVG in `assets/`, generated by one script. Nothing in `assets/` or `README.md` is edited by hand.

```
python tools/build.py 13   # 13 = the next asset version
```

`build.py` writes every SVG into `assets/` and regenerates `README.md` from `tools/README.template.md`, adding `?v=<version>` to every image URL. GitHub caches README images hard, so the version has to go up on every change or visitors keep seeing the old files. The current version is in the image URLs in `README.md`.

Python 3.10+ and the standard library only.

## What is where

| file | what it is |
|---|---|
| `tools/build.py` | palette, every section and every animated diagram |
| `tools/README.template.md` | page order and links; `A/` marks an asset path |
| `tools/contrib.json` | public contribution calendar used by the heatmap and snake |
| `tools/fetch_contributions.py` | refreshes `contrib.json` from github.com |
| `tools/refresh.py` | daily job: fetches, then rebuilds at the next version if activity changed |
| `.github/workflows/refresh-heatmap.yml` | runs `refresh.py` every day at 06:17 UTC |

## Daily heatmap refresh

The commit log updates itself. A GitHub Action runs `tools/refresh.py` once a day, and if the contribution calendar has changed it rebuilds with the next asset version and commits. On days with no change it does nothing, so the version only moves when there is something new.

The commits are authored by `github-actions[bot]`, so they do not count on the contribution calendar. It can be run by hand from the repo's Actions tab with **Run workflow**. Because the bot also bumps the version, run `git pull` before building locally, and take the next number from the image URLs in `README.md`.

GitHub pauses scheduled workflows after 60 days with no repository activity. If that happens, the Actions tab shows a button to turn it back on.

## How the motion works

GitHub strips `<style>`, `style=` and scripts from a README, so nothing on the page can react to hover or scroll. CSS inside an SVG loaded as `<img>` does run, so every animation lives inside its SVG and plays on a loop:

- Each project and research diagram is one looping scene on a single clock. Elements draw on, captions write in, and the key result gets circled or pulsed, in the style of 3Blue1Brown.
- The hero is a Fourier series: 80 nested rotating circles whose tip traces the initials, synced with the ink trail. The taglines under the name rotate on their own clock.
- The heatmap snake uses SMIL `animateMotion` and eats the real contribution squares, nearest first.

With reduced motion turned on, every scene rests on its finished frame instead of an empty one.

## Themes

The cards carry their own dark background, so they read the same on GitHub's light and dark themes. Section headers are transparent, so each has a `-light.svg` twin served through `<picture>` with a `prefers-color-scheme: light` source.

## Palette

Sodium: amber accent `#FFB547` on warm, tinted near-black panels. The values live in `PALETTES` at the top of `build.py`. The other two palettes there are kept for comparison and are not built.
